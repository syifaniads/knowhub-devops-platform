# Repository Provenance

## Why there were multiple repositories

The project evolved from personal experimentation into a team organization. That created duplicate-looking repositories with shared Git history.

### 1. `syifaniads/react-firebase-devops`
Early personal development repository. It contains Syifani-authored React/Firebase/DevOps history and is now the canonical personal portfolio view.

### 2. `syifaniads/tes`
Later personal mirror/working copy. Its final frontend commits are shared by SHA with the organization frontend. The generic name makes it a poor recruiter-facing repository, so it is deprecated.

### 3. `Final-Project-DevOps/devops-platform-frontend`
Final team frontend source. Many commits are identical by SHA to the personal lineage.

### 4. `Final-Project-DevOps/devops-platform-backend`
Final team backend source and backend CI/container artifacts.

### 5. `Final-Project-DevOps/infrastructure`
Later infrastructure/documentation consolidation. Useful for understanding the topology, but created after the original project and therefore not used to rewrite the historical timeline.

## Portfolio decision

Recruiters should start here:

**`syifaniads/react-firebase-devops`**

Then follow source-evidence links to the team organization when they want implementation-level provenance.
